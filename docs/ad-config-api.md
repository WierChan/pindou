# /api/config 改造：流量主广告位下发（pindou-server 实现）

小程序端已完成（`utils/config.js` 消费、`utils/ads.js` 统一封装），后端按本文档改一个
**已有接口的响应结构**即可联调。无新增接口、无新增数据表。

先划清边界：广告素材、投放、计费、结算全部在微信流量主侧闭环，后端**只负责告诉客户端
「哪个广告位用哪个 adUnitId」**。后端不代理广告请求、不存广告素材、不做频控记账。

## 0. 一句话总结

`GET /api/config` 的 `data`：**删 2 个字段、1 个字段进入灰度、新增 1 个对象字段**。

## 1. 接口与鉴权（均不变）

- `GET /api/config`，Bearer token（与 /api/works 一致），统一响应 `{code, message, data}`（code 0 成功）。
- 客户端只在**冷启动**拉一次（登录成功后），失败沿用上次本地缓存。所以：
  - 不用考虑此接口的高频压力，不需要配置推送通道；
  - 后台改完值，客户端**下次冷启动生效**——这就是"不发版开关广告"的全部机制。

## 2. data 字段对照

| 字段 | 类型 | 改动前 | 改动后 |
|---|---|---|---|
| debug | bool | 调试开关 | **不变** |
| swipeAdSeconds | int | 滑动解锁时长 | **删除**（见 §4） |
| swipeAdUnitId | string | 滑动激励位 ID | **删除**（见 §4） |
| freeRowUses | int | 整排免费次数 | **灰度期保留原值下发**，旧版客户端淘汰后删（见 §4） |
| adUnits | object | — | **新增**，流量主广告位表，见 §3 |

## 3. adUnits 明细

| key | 广告类型 | 客户端挂载点 | 备注 |
|---|---|---|---|
| bannerHome | banner | 首页作品列表底部 | 列表为空（新用户零作品）时客户端不渲染 |
| bannerTpl | banner | 创建页「图案库」tab 底部 | |
| rvChart | 激励式视频 | 分享弹窗「保存图纸」前置 | 同一作品当天只要求看一次（客户端本地记账） |
| rvExport | 激励式视频 | 自由画布「📤 导出」前置 | 同上 |
| interstitialDone | 插屏 | 熨烫完成弹窗「回到首页」时机 | **二期再配**，先跑前四个看数据 |

取值规则：

- 值 = 流量主后台「广告位管理」建单元后生成的 `adunit-xxxxxxxx`，string；
- **空串或缺 key = 该位关闭**；整个 `adUnits` 缺省 = 全部关闭（客户端等价处理，
  但建议始终带上完整五键的对象，联调直观）；
- 非 string 值客户端一律按空串处理。

## 4. 旧字段处置与灰度

- `swipeAdSeconds` / `swipeAdUnitId`：**可立即删**。旧版客户端读到缺省（0 / 空）恰好是
  它自己的"广告未接入"关闭态（免费体验弹窗照常），无任何副作用。
- `freeRowUses`：若线上还有旧版本客户端在跑，**继续按原值下发**——旧版读到缺省 0 会把
  「整排拼豆」锁死并提示"免费次数用完"，属于体验事故。新版客户端完全忽略此字段。
  删除时机：mp 后台「版本分布」里旧版占比清零。
- 若小程序从未对外发布过正式版/体验版，三个字段一次删干净即可，无灰度问题。

背景（为什么拆）：「看广告限时解锁滑动 / 整排 ×N 次数」是道具化的游戏机制，与工具类
定位冲突（也贴着"核心功能不得锁在广告后面"的流量主红线）；两者已改为常驻免费工具，
广告改挂在「保存图纸 / 区域导出」等增值产出上。

## 5. 存储与校验建议

- 一张 kv 配置（或复用现有 config 存储）即可，要求：**改值即生效于接口响应**，不用重启服务。
- 建议做最小 sanity check：非空值须匹配 `/^adunit-[0-9a-zA-Z]+$/`，不匹配则按空串下发并
  告警。贴错 ID 客户端不会炸（banner 走 binderror 隐藏、激励走 onError 放行），但会白瞎曝光，
  后端拦一道更省心。
- **不需要做的事**：广告请求代理、素材存储、观看频控（客户端本地记账）、人群定向（流量主侧自动）。

## 6. 分阶段配置与示例响应

### 阶段 0 · 现在（配合本次客户端发版）

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "debug": false,
    "freeRowUses": 3,
    "adUnits": {
      "bannerHome": "",
      "bannerTpl": "",
      "rvChart": "",
      "rvExport": "",
      "interstitialDone": ""
    }
  }
}
```

`freeRowUses` 仅为旧版客户端保留（无旧版则整行删掉）。此阶段客户端表现：页面无任何
广告痕迹，「保存图纸」「导出」免费直行——即当前上线可用状态。

### 阶段 1 · UV ≥ 500，开通流量主后

mp 后台开通流量主 → 「广告位管理」建 4 个单元（2 banner + 2 激励式视频）→ 填入：

```json
"adUnits": {
  "bannerHome": "adunit-xxxxxxxxxxxxxxxx",
  "bannerTpl": "adunit-xxxxxxxxxxxxxxxx",
  "rvChart": "adunit-xxxxxxxxxxxxxxxx",
  "rvExport": "adunit-xxxxxxxxxxxxxxxx",
  "interstitialDone": ""
}
```

无需发版，客户端下次冷启动四个位全亮。哪个位想关，清空对应值即可。

### 阶段 2 · 前四位数据稳定后

建插屏单元，补 `interstitialDone`。插屏是最易招差评的形态，务必单独观察留存再决定去留。

## 7. 联调验收清单

阶段 0 可验（不需要真 adUnitId）：

| # | 后端配置 | 预期客户端表现 |
|---|---|---|
| 1 | adUnits 全空 / 缺省 | 首页、图案库无 banner；保存图纸/导出直接执行 |
| 2 | 首页空状态（删光作品） | 即便 bannerHome 有值也不渲染 banner |
| 3 | 老缓存兼容：老版本 data（含 swipeAd*）落过本地缓存后升级 | 客户端读老缓存自动退化为全关，不报错 |

阶段 1 拿到真 ID 后补验：

| # | 后端配置 | 预期客户端表现 |
|---|---|---|
| 4 | bannerHome 填真 ID | 首页列表底部出 banner；清空后冷启动消失（验证不发版开关） |
| 5 | bannerHome 填非法 ID | binderror 触发，容器整体隐藏，页面无空坑 |
| 6 | rvChart 填真 ID | 「保存图纸」先弹"看广告"确认 → 完整看完才保存；中途退出不保存；同一作品当天第二次免看直存 |
| 7 | 激励视频无库存/加载失败 | 直接保存（静默放行） |
| 8 | interstitialDone 填真 ID | 熨烫完成点「回到首页」弹插屏，关掉后正常回首页 |

## 8. 客户端已实现的降级兜底（后端无需任何配合）

- 位 ID 空：banner 不渲染；激励直接放行；插屏不弹
- banner 加载失败：容器整体隐藏，不留空坑
- 激励视频拉取/播放失败、无库存：直接放行功能（工具功能永不被广告卡死）
- 激励视频完整看完（isEnded）才发放；中途退出不发放
- 按作品记账：同一作品同一位当天只看一次（本地 storage）
